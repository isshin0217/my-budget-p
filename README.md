# 카드 문자 가계부 (iPhone + Windows)

카드 승인 문자(SMS)를 읽어 **금액·가맹점·날짜·카테고리**로 정리하는 가계부.
맥북 없이 **아이폰 + 윈도우**만으로 동작하도록 설계.

## 지금까지 만든 것 (동작 확인됨)

| 파일 | 역할 |
|------|------|
| `apps_script/` | **폰 실시간용.** 구글시트 웹앱 — 문자 수신 → 파싱 → 기록 → 알림 + 대시보드 |
| `parser.py` | 카드 문자 1건 → 구조화 데이터. 취소는 음수 처리, 가맹점 자동 분류, 카테고리→주기 매핑 |
| `ledger.py` | 엑셀(`가계부.xlsx`) 누적 저장. 중복 방지·날짜 정렬·태그 보존·스키마 마이그레이션 |
| `report.py` | 고정비 자동 감지 + `주간요약`/`월간요약` 시트 생성 |
| `run.py`    | 문자 뭉치를 파싱해 저장하고 **이번 주 현황을 터미널에 출력** |
| `check_port.py` | 파이썬과 `Code.gs` 의 로직이 일치하는지 대조 |

```bash
python run.py messages.txt    # 문자들을 붙여넣은 파일에서 읽기
python run.py --week          # 새 문자 없이 이번 주 현황만 다시 보기
python run.py --demo          # 데모 데이터로 만들어 보기
```

## 이번 주에 얼마 더 써도 되나 (핵심 기능)

예산은 **주 단위**로 보고, 카드값은 **한 달에 한 번** 빠져나간다.
주기가 서로 다르므로 둘을 따로 센다. 문자를 넣을 때마다 바로 뜬다.

```
  이번 주  07/20 ~ 07/26   (남은 6일)
  ■■■■■■■■■·····················  138,500 / 443,011원

  더 써도 되는 돈   304,511원   (하루 50,751원 페이스)
  지금 선결제할 금액 211,400원

  · 월 고정비 72,900원 (SKT통신요금, 넷플릭스) 은 주간 한도에서 미리 뺐습니다.
```

계산 모델:

```
주간 가용액     = (월 예산 − 월 고정비) ÷ 4.35
이번 주 남은 돈 = 주간 가용액 − 이번 주 변동비
이번 달 카드값  = 이번 달 카드 승인 총액 (고정비 포함)
```

고정비는 월 예산에서 이미 뺐으므로 주간 한도에서 **또 빼지 않는다**.
다만 카드로는 실제로 나갔으므로 **카드값에는 포함**된다. 이 둘을 구분하는 게 핵심.

### 통장 잔액이 한도를 깎는다 (`apps_script/` 전용)

예산은 계획이고 통장 잔액은 현실이다. 계획만 보면 통장이 −800,000원인데도
화면은 "이번 주 310,000원 쓸 수 있다"고 말한다. 맞는 말이지만 쓸 수가 없다.

`설정` 시트의 `Account balance` 를 적어두면 한 겹이 더 붙는다.

```
실제 한도 = 주간 가용액 − max(0, −마이너스한도 − 예측 최저잔액)
```

현재 잔액을 그대로 빼지 않는 게 요점이다. 25일에 월급이 들어온다면 지금
마이너스인 건 사고가 아니다. 급여·카드 결제일·고정비를 하루씩 굴려 앞으로 35일의
**최저점**을 구한 뒤, 그 최저점이 `Overdraft limit` 아래를 뚫는 만큼만 깎는다.
마이너스 통장 한도 안에서 노는 건 건드리지 않는다.

깎이면 한도·페이스·'이번 주 남은 돈'이 전부 따라 움직인다. 얼마가 왜 깎였는지는
화면 맨 아래 **"How the limit was worked out"** 을 펼치면 나온다 — 위쪽에 경고 배너로
띄우지 않는다. 최저점 날짜가 대개 '오늘'이라(말일 결제면 급여일까지 통장에서 나가는
게 없다) 날짜를 알려줘 봐야 적어둔 잔액을 되풀이하는 것뿐이었다.

잔액을 안 적어두면(0) 이 층 자체가 없다 — 파이썬 쪽(`report.py`)에는 이 층이
없으므로 `check_port.py` 대조 때 감안할 것.

`Could save this month` 도 마이너스 잔액만큼 뺀 값을 보여준다(메우기 전엔 저금이
아니므로). 단 `Monthly` 시트의 `Saved` 열에는 그 달의 흐름(수입 − 지출)이 그대로
남는다 — 재고인 잔액을 섞으면 구멍이 메워질 때까지 달마다 거듭 차감되기 때문.

### 돈을 두 축으로 나눈다

- **주기** (자동) — `고정`(통신·구독·보험) / `주기`(장보기·옷·주유) / `일상`(밥·카페·교통)
  - 고정비는 **자동 감지**: 같은 가맹점이 26~35일 간격으로 15% 이내 금액 반복 → 고정비 판정
  - 데이터가 2개월 쌓여야 잡히므로, 그전에는 `설정` 시트의 `월 고정비(수동)`을 쓴다
  - **마지막 결제가 40일을 넘으면 자동으로 풀린다.** 끊은 구독이 계속 예산을 깎지 않도록
- **태그** (수동) — 데이트·여행처럼 문자만 봐선 알 수 없는 것
  - `내역` 시트의 노란 `태그` 칸에 직접 적으면 다시 실행해도 **보존**된다
  - 같은 가맹점은 **다음부터 자동으로 같은 태그**가 붙는다 (쓸수록 손이 덜 감)

**둘 다 학습하지만 기준이 다르다** (구글시트 쪽):

| | 학습 조건 | 왜 |
|---|---|---|
| 카테고리 | **1번만 고쳐도** 물려받음. 여러 번 고쳤으면 **가장 나중 것** | 가맹점의 성질이라 방문마다 안 변한다. 티머니는 언제나 교통. 많이 쓰인 쪽을 따르면 옛 행 스무 줄이 오늘 고친 한 줄을 이겨, 고쳐도 안 바뀌는 것처럼 보인다 |
| 태그 | **같은 값 2번 이상**이어야 물려받음 | 방문마다 성격이 다르다. 스타벅스를 한 번 '데이트'로 적었다고 혼자 마신 커피까지 데이트가 되면 안 된다 |

주기(고정/주기/일상)는 파이썬 쪽 `월간요약` 의 '주기별' 집계에만 쓴다.
구글시트 `Ledger` 에는 그 열을 두지 않는다 — 카테고리에서 언제든 나오는 값인데
시트에 적어두면 아무도 안 읽는 칸이 하나 더 생길 뿐이다.

'사람이 고쳤다'는 판별은 숨은 `AutoCategory` 칸으로 한다 — 저장하던 **그때** 규칙이
내놓은 값을 같이 적어두고, `Category` 가 그와 다르면 사람이 고친 것으로 본다.
*오늘의* 규칙과 비교하면 안 된다. 키워드를 하나 고치거나 카테고리를 쪼개는 순간
그 가맹점의 과거 행이 전부 '사람이 고친 것'으로 둔갑해, 새 결제에 옛 카테고리를
도로 물려주고 규칙 변경이 영영 반영되지 않는다.

규칙을 바꿨으면 메뉴의 **Budget → Clean up ledger** 를 한 번 누른다. 손대지 않은
과거 행(`Category` = `AutoCategory`)을 지금 규칙으로 다시 분류해, 지난달과 이번 달이
같은 이름으로 묶인다. 사람이 고친 행은 건드리지 않는다.

**정리 작업은 사람이 타이핑했을 수 있는 값을 절대 덮어쓰지 않는다.** `AutoCategory`
칸이 생기기 전에 저장된 행에는 *지금 규칙이 내놓는 값*을 적어 넣고 `Category` 는
그대로 둔다. 그러면 시트 값이 규칙과 다른 행은 저절로 '사람이 고친 것'으로 남는다.

> 반대로(빈 칸에 `Category` 를 복사) 하면 손으로 고쳐둔 행이 전부 '규칙대로 저장된
> 것'으로 읽혀 규칙 값으로 되돌아간다. 고친 게 몇십 줄이면 그게 다 날아가는데,
> 되돌릴 수도 없고 그 사실이 화면 어디에도 안 남는다.

대신 규칙을 바꿔도 **옛 행은 옛 이름을 지킨다** — 사람이 고친 것처럼 보이기 때문이다.
그 가맹점의 새 결제가 옛 이름으로 들어오면 한 번만 고쳐주면 된다. 학습이 가장 나중에
고친 값을 따르므로 그 한 번으로 굳는다.

### 설정

`가계부.xlsx`의 `설정` 시트에서 직접 수정한다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| 월 예산 | 2,000,000 | 한 달에 쓸 수 있는 총액 |
| 주 시작 요일 | 월 | **카드 선결제 주기에 맞출 것** |
| 월 고정비(수동) | 0 | 0이면 자동 감지만 사용 |

### 달이 바뀌면

`Ledger` 한 장에 계속 쌓인다. 달마다 시트를 새로 만들지 **않는다** —
고정비 자동 감지(2개월 필요), 지난달 비교, 카드값 예측, 태그·카테고리 학습이
전부 여러 달치를 한꺼번에 읽기 때문이다.

대신 두 가지로 달을 구분한다.

- **`Monthly` 시트** — 달마다 한 줄. 카드/카드밖/총지출/월급/저축/예산/상위 카테고리.
  **말일에 들어온 결제로만** 기록된다. 한 달 내내 덮어쓰면 숫자가 출렁이고, 달이
  끝나기 전 값은 어차피 중간 결과라 남길 이유가 없다. 지나간 달 줄은 건드리지 않는다.
  말일에 결제가 없어 줄이 안 생겼으면 메뉴의 **Budget → Update monthly** 로 남긴다.
- **`Ledger` 의 달 구분** — 달마다 배경색이 번갈아 칠해진다. 정렬할 때마다 다시 칠하므로
  손으로 행을 넣어도 유지된다.
  선은 긋지 않는다 — 선은 데이터가 아니라 '그 자리'에 남는데, 새 결제가 들어올 때마다
  정렬로 행이 움직여도 따라가지 않아 엉뚱한 줄에 밑줄이 쌓였다.

구글시트(`Settings`)에만 있는 항목:

| 항목 | 설명 |
|---|---|
| `Cycle length (days)` | `Month` 면 달력 한 달(1일~말일), `7` 이면 주 단위 |
| `Account balance` | 지금 통장에 있는 돈(직접 입력). 적어두면 이 값이 주간 한도를 깎는다. 0 = 안 씀 |
| `Overdraft limit` | 마이너스 통장 한도. 잔액이 0 아래로 가도 이 안이면 경고하지 않고 한도도 안 깎는다 |
| `Monthly income` | 월급. 잔액 예측 + '이번 달 저금 가능액' 계산에 쓴다 |
| `Card payment day` | 카드값이 통장에서 빠지는 날. 0 = 안 씀 |
| `Overseas fee %` | 외화 결제에 환율 위로 얹는 수수료(브랜드+해외이용). 기본 1.3 |
| `FX fallback` | 실시간 환율을 못 구할 때만 쓰는 환율. 예: `JPY=9.1, USD=1380` |

### 해외결제는 추정치로 들어간다 (`apps_script/` 전용)

외화로 찍힌 해외승인 문자(`JPY 2,000.00` 처럼)는 **외화 × 환율 × (1 + 수수료)** 로
원화를 추정해 저장한다. 환율은 숨은 `FX` 시트의 `GOOGLEFINANCE` 에서 가져온다.
근거는 원장 `Foreign` 열에 `JPY 2,000.00 @9.12 +1.3%` 처럼 남는다. 실제 청구액은
매입일 환율로 며칠 뒤 정해지므로 청구서가 나오면 `Amount` 만 고치면 된다.

해외 취소는 같은 카드사·통화·외화 금액의 승인을 찾아 **그 원화 금액 그대로** 뺀다
(환율을 다시 적용하면 몇십 원씩 찌꺼기가 남는다). 짝이 없는 `PENDING` 취소는
Uber 같은 곳의 임시승인 해제라 저장하지 않는다 — 임시승인 문자를 안 보냈다면
되돌릴 지출도 없기 때문이다. 파이썬 `parser.py` 는 환율이 없어 외화 문자를 파싱
실패로 돌려보낸다.

### 카드 청구서는 원장 합계 그대로다

`Card payment day` 를 적어두면 잔액 예측에 카드 청구서가 카드사별로 한 줄씩 선다.
금액은 **원장 합계 그 자체**다 — 예산·고정비에서 나온 숫자를 섞지 않는다. 그래야
카드사 앱의 결제 예정액과 바로 견줄 수 있고, 어긋났을 때 원장이 틀린 건지 예산이
틀린 건지 가려낼 수 있다.

어느 결제에 실리는지는 **그 날짜 이후 처음 오는 결제일**로 정한다. 결제일이 말일이면
그 달 전체가 한 장이 되고, 15일이면 16일에 쓴 것은 다음 장으로 넘어간다.

아직 안 쓴 몫(하루치 × 남은 날)은 `Spending still to come` 이라는 **별도 줄**로 같은
날에 선다. 이게 없으면 앞으로 쓸 돈이 통장에서 영영 안 나가 최저 잔액이 부풀고,
그 최저점으로 주간 한도를 깎는 층(위 참고)이 늘 0이 된다.

지원 문자 형식 (신한카드):
```
[Web 발신]
신한카드(1234)승인 홍*동 94,400원(일시불)07/01 19:55 폴리스 유한

[Web발신]
신한카드 (1234)  매출취소  홍*동  29,902원  07/12 네이버페이

[Web발신]
현대카드Z ontact 승인
홍*동
10,000원 일시불
07/27 17:10
모바일티머니선
누적206,250원
```
> 취소 문자는 승인과 형식이 다르다 — `취소` 가 아니라 `매출취소` 이고 **시각이 아예 없다.**
> 시각이 없으면 00:00 으로 본다. 날짜만 맞으면 주간 계산은 그대로 맞다.
>
> 현대카드는 **카드번호 괄호가 아예 없다.** 기본 정규식은 `(1234)` 을 기준점으로 문장을
> 끊으므로 이 형식은 통째로 실패한다. 그래서 기준점을 `승인/취소` 로 바꾼 두 번째
> 정규식(`_APPROVAL_NO_NUM_RE`)을 두고, 첫 번째가 실패했을 때만 쓴다.
> 이쪽이 훨씬 헐거워서 순서를 바꾸면 신한카드 문자의 캡처가 어긋난다.
> 다른 카드사는 문구가 달라 파서 규칙 추가가 필요합니다. 실제 문자 예시를 모으면 대응.

## 전체 그림

밖으로 내보내는 방식으로 갑니다 (완전 무인 자동은 불가, "한 번 탭" 방식).

```

   │  단축어(Shortcut): 문자 텍스트를 전송
   ▼
[구글]   Apps Script 웹앱 → 파싱 → 구글시트에 한 줄 추가
   │        (PC가 꺼져 있어도 동작, 폰에서 바로 확인)
   ▼
[윈도우]  (선택) 파이썬이 구글시트를 읽어 월별 엑셀 리포트 생성
```

- **구글시트**가 살아있는 가계부 → 폰·웹 어디서나 열람, .xlsx 내보내기 가능
- 파싱 로직은 지금 `parser.py`(파이썬)로 검증 → 나중에 Apps Script(JS)로 이식

## 남은 단계 (로드맵)

1. ~~월별 요약 리포트~~ — 완료. 주간요약(핵심) + 월간요약
2. ~~구글시트 연동~~ — 코드 완료. [`apps_script/설치안내.md`](apps_script/설치안내.md) 대로 설치하면 폰에서 실시간
3. **[다음] 카드사별 문자 예시 수집** → 파싱 규칙 확장 (해외승인/할부 등).
   `parser.py`와 `Code.gs` **양쪽 다** 고쳐야 한다
4. **배포 패키지** — 단축어 링크 + 설치 안내서

## 파이썬과 Apps Script는 같은 모델

파싱·분류·주간 계산 로직이 양쪽에 이식돼 있고 **같은 숫자를 낸다.**
규칙을 고칠 때 한쪽만 고치면 폰과 엑셀의 숫자가 갈린다. 반드시 양쪽을 같이 고치고,
아래로 확인할 것:

```bash
python check_port.py    # 정규식·키워드·주기·주 계산·고정비 기준 대조
```

> **현재 차이**: `Fixed`(항목별 고정비)와 `Extra`(환급·캐시백) 시트는 Apps Script에만 있다.
> 파이썬 쪽은 아직 모르므로, 엑셀로 뽑은 주간 한도는 이 둘을 반영하지 않는다.
> '이번 달 카드값'도 Code.gs에만 있고, 파이썬은 아직 '이번 주 카드 총액'을 보여준다.
> 구글시트가 실제 가계부이므로 당장 문제는 없지만, 파이썬을 다시 쓸 거면 맞춰야 한다.
>
> 파싱·분류·주 계산은 여전히 양쪽이 같고, `check_port.py` 가 그것만 대조한다.

## 완전 자동(탭 없이)을 원하면

- 카드 알림을 **이메일**로도 받게 설정 → 파이썬이 메일을 자동으로 읽어 파싱.
  아이폰/윈도우만으로 유일하게 "무인 자동"이 가능한 경로.
